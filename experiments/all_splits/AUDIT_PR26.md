# PR #26 模型代码审查（2026-11-23）

审查对象：`experiment/trial-iter30_adding-one-fixed-configuration-h` 的 `neuroasd/model.py`、`ensemble.py`、`linear_baseline.py`。

## 1. 有没有偷看测试数据：没有

- 不读 `test.y`，不碰数据源内部，不读数据文件（运行时有保护，读 data/ 会报错）。
- 测试的人只作为"特征"参与，所有统计量都只用训练数据算：tangent 参考点、标准化的均值和方差、连接挑选、正则强度、ASD 权重、分界线、组合权重。
- 每人的连接收缩只用这个人自己的矩阵；不用测试站点其他人的分数（自检会把测试集整体、分两半、单人各算一次，结果必须一致）。

## 2. 打乱标签测试：通过

把训练数据的 ASD / 对照标签随机打乱再训练，用真实标签评测测试站点。没有泄漏的模型应该接近 0.5。

| 测试站点 | 人数 | 真实标签 AUC | 打乱标签 AUC |
|---|---|---|---|
| NYU | 161 | 0.816 | 0.517 |
| USM | 81 | 0.924 | 0.404 |
| UM_1 | 81 | 0.823 | 0.538 |
| ABIDEII-SDSU_1 | 47 | 0.976 | 0.560 |
| 平均 | | 0.885 | 0.505 |

## 3. 不是作弊、但会让分数偏乐观的地方

1. **在同一批测试站点上反复挑方案**：自动实验试了约 30 轮，只保留在这 1,120 人上分数最高的。挑出来的分数天然偏高。证据：锁定的 323 人上，对照 recall 只有 66%，明显低于开发集上的 74%–75%。
2. **"预先固定"的参数其实是看过结果后定的**：保留连接数 20000 / 8000 / 12000、正则强度 0.01 / 0.1、ASD 权重 1 / 2 / 4、树模型的配置，每一轮内部没有用测试数据调，但它们是在前几轮结果的基础上定的，属于第 1 点。
3. **训练内部的小问题（不涉及测试数据）**：
   - 训练内部交叉验证时，特征标准化和 tangent 参考点用的是全部训练数据，包括内部验证的那部分（不看标签）。
   - 定分界线时，组合模型是在同一批训练行上拟合再打分。

   这两点让训练内部的分数略偏乐观，分界线因此在新机构上偏松，是锁定集上对照 recall 下降的可能原因之一。

## 结论

代码是真实、按规则写的，没有偷看测试答案；打乱标签后模型就失效，说明分数来自真实信号。
但开发集上的分数因为反复挑选而偏乐观，可信的是锁定 323 人上的分数。
